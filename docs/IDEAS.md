# IOL Order アイデア・将来構想

最終確認日: 2026年10月27日（日本時間）

未確定の案、将来構想、保留事項と採否の根拠を管理する。実装方針が決まったものの優先順位・進捗は [ROADMAP.md](ROADMAP.md) を正とし、ここから参照する。

## 状態の意味と運用

| 状態 | 意味 |
| --- | --- |
| 採用 | ユーザーの指示などで実装する方針が決まった。ROADMAPの対応IDを付ける。実装・テスト・公開の完了を意味しない |
| 検討中 | 議題として記録した段階。採否・仕様・優先順位・担当は未確定。過去資料の「将来」「未実装」「残課題」だけでは採用にしない |
| 保留 | 現行で停止中、または先行条件を満たすまで実施を待つ記録がある。再開・採用の判断は別途行う |
| 見送り | 不採用・廃止が明示されている。理由と範囲を残す。未実装というだけでは見送りにしない |

各項目に状態、概要、決めること、出典を残す。新たな提案は原則として「検討中」で記録し、ユーザーが最終決定する。採用時にはROADMAPへ追加し、ここにも対応IDと決定の根拠を残す。担当AIは明示的な割り当てがなければ未定。以下の未確定案にも担当を割り当てていない。

## 今回指定された未確定の構想

### I04 ディーラーの受注確認ステータス

- **状態**: 検討中。
- **概要**: ディーラーが注文内容を確認したことを記録し、医療機関側でも確認できるようにする。
- **決めること**: 「確認済み」「受注済み」などの意味、更新する人、明細単位か注文単位か、訂正・履歴・通知の要否。現在のメール送信受付・配信結果とは別の状態として扱う必要がある。
- **出典・関連**: 今回のユーザー指定、[メールの送信・配信の区別](order-mail.md)。R06の追加仕様候補であり、採用範囲にはまだ含めない。

### I05 ディーラーの会社・担当者別アカウント管理

- **状態**: 検討中。
- **概要**: ディーラーの会社と個々の担当者を分けて管理し、担当施設や注文に応じたアクセスを設定する。
- **決めること**: 会社内の管理者、担当者の追加・退職・担当替え、担当範囲、他社や他施設とのデータ分離。ログイン方式・権限モデルは未決定。
- **出典・関連**: 今回のユーザー指定。R06の設計で検討するが、会社・担当者別の方式を確定したものではない。

### I06 CSV出力・ディーラー社内システムとの連携

- **状態**: 検討中。
- **概要**: 受注データをCSVなどで取り出し、ディーラーの既存業務システムで利用する。
- **決めること**: 必要な項目、形式・文字コード、出力権限、取込先、API連携の要否、重複取込時の扱い。連携先の仕様確認が必要。
- **出典・関連**: 今回のユーザー指定。採用済みのR07（印刷・Excel出力）とは別案。

### I07 施設設定・初期導入作業のさらなる簡略化

- **状態**: 検討中（事前登録の範囲はI01として採用済み）。
- **概要**: 担当医・採用IOL・ディーラー・メール設定など、利用開始前の作業を減らす。
- **決めること**: どの入力・確認を簡略化するか。設定テンプレートや一括取込などの具体方式は未採用。施設固有の宛先・担当者等を誤って引き継がない確認方法も決める。
- **出典・関連**: 今回のユーザー指定、[施設事前登録](facility-preregistration.md)。R01・R10に関連。

### I08 重複施設の統合

- **状態**: 検討中。
- **概要**: 誤って二重登録された施設について、所属・設定・履歴などを整理する方法を検討する。
- **決めること**: 同名の別施設との識別、統合先、権限、注文番号・過去の注文記録・参加待ちの扱い、戻せる範囲。現在ある重複候補の警告は統合機能ではない。施設名の一致だけで自動統合しない。
- **出典・関連**: 今回のユーザー指定、[施設登録申請](facility-applications.md)、[施設事前登録](facility-preregistration.md)。統合処理は未実装。

### I09 施設登録承認権限の限定的な委任

- **状態**: 検討中。
- **概要**: 信頼できる担当者に、施設登録の申請一覧・承認・却下だけを委任する。
- **決めること**: 対象者、付与・取消手順、操作範囲、自己承認の禁止、操作履歴。承認権限だけで施設の注文履歴や取引情報まで閲覧できる設計にしない。
- **出典・関連**: 今回のユーザー指定、[facility-applications.mdの将来の委任](facility-applications.md)、[canApproveFacilities](../functions/src/roles.js)。現在はplatformAdminのみ。資料の専用クレーム名は例示で、実装済みではない。

### I10 AIエージェントによる開発・テスト・マニュアル更新の自動化

- **状態**: 検討中。
- **概要**: 開発・検証・仕様変更に応じたマニュアル更新を連動させ、記録の更新漏れを減らす。
- **決めること**: 自動化する範囲、担当AI、実行契機、レビュー方法、複数AIの作業分担・競合回避、失敗時の対応。文書案・テスト実行・コード変更・本番公開は分けて範囲を決める。
- **出典・関連**: 今回のユーザー指定。自動採用・自動公開を認める決定ではない。ユーザーによる最終決定と、既存の本番操作ルールを維持する。
