## (1) トリガーの呼び出し権限(承認済み・実施済み)
- 原因: Eventarc トリガーの実行アカウント `iol-functions-dev` に Cloud Run の呼び出し権限がなく、Firestore のトリガー(申請の通知・注文メールの作成時の送信・設定の変更履歴)が 401 で失敗していた。
- 対応: 6つのサービス(`sendordermail`・`notifyfacilityapplication`・`auditorderers`・`auditadoptediols`・`auditfacilitydealers`・`auditfacilitysettings`)だけに、`iol-functions-dev` の `roles/run.invoker` をサービス単位で付与。プロジェクト全体への付与・未認証の呼び出しの許可はしていない。
- 確認: 付与後の 401 は、付与の直後(権限の反映前)に1回だけで、その後は6つとも 401・エラーなし。審査中の申請の通知は、保留中のイベントの再試行で自動送信され、通知の状態は「受付(運営者宛て)」に更新。注文メールの記録は1件のまま(送信1回・配信済み。二重送信なし。保留イベントの再実行は起きていない)。設定の変更履歴は、溜まっていた6件が記録され、同じイベントの重複なし。

## (2) 申請の削除(ブランチ `feature/application-delete`。デプロイ・本番の削除は承認待ち)
- サーバー(`deleteFacilityApplication`): 運営者(platformAdmin)のみ(施設登録の承認権限を委任しても、削除は運営者だけ)。審査中・却下済みだけ削除でき、承認済みは施設との整合性のため削除不可。1回のトランザクションで、申請の削除・申請者の申請枠の1件ぶんの返却・運営者の操作履歴(`platformAuditLogs`。申請者のメールは伏せ字)の記録を行う。施設・所属・注文には触れない。削除後は重複判定(審査中の申請との照合・同じ人の同名の再申請)に数えない。削除した申請の通知は送らない。
- Rules: `platformAuditLogs` はクライアントから読み書き不可(運営者を含む)。
- 画面: 申請の一覧の審査中・却下済みに控えめなゴミ箱。確認ダイアログの後に削除。承認済みには出さない。
