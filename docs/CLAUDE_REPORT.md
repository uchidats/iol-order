## 調査と方針
- 担当医マスター(`facilities/{id}/orderers`)には、すでに任意項目 `email` がある。ログインユーザー(認証情報)は uid・email・emailVerified を持つ。→ **既存の `email` と認証済みアカウントのメールアドレスの一致**で紐づける。新しい項目・Firestore スキーマ・Rules・Functions の変更、デプロイは**不要**(そのため実装前の報告は不要と判断)。UID での紐づけは、担当医マスターに uid の項目を追加する必要があり(Rules変更・デプロイが必要)、今回は採用していない。

## 変更内容
- ログインユーザー本人の担当医(メールアドレスが一致)がいれば、**最初のレンズと、入力を初期状態に戻したとき**の担当医の初期値を本人にする。プルダウンから別の医師に変更できる。
- 紐づけはメールアドレスのみ(氏名だけでは判定しない。大文字小文字・全角半角は同じ扱い)。メール未確認のアカウント、同じメールの医師が複数いて決められない場合、紐づかないユーザー(CO・看護師・事務職員など)、担当医のメール未登録は、従来どおり未選択。
- 「レンズを追加」は、従来どおり直前の担当医(現在の選択)を引き継ぐ(こちらを優先。本人に戻さない)。
- 注文者(ログインユーザー=`createdBy`、サーバーが記録)と担当医(執刀医)は別情報のまま。サーバーへ送る内容・注文データは変更なし。
- 実装: `src/domain/self-doctor.js`(新規 `findSelfDoctor`)、`src/ui/lens-lines.js`(`getDefaultDoctorId`)、`src/ui/order-form.js`、`src/main.js`(ログインユーザーの uid/email/emailVerified を渡す)。文書: `docs/doctor-per-line.md`。
- 運用: 医師本人のログイン用メールアドレスを、施設設定「担当医」のメールアドレスに登録しておくと、その医師でログインしたときに本人が初期選択される。現在の開発データでは、立川病院・せんじゅ眼科の担当医「内田」のメールがログイン用アカウントと同じため、そのアカウントでは「内田」が初期選択される見込み(データは変更していない)。
