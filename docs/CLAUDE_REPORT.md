## 変更内容(詳細は `docs/dealer-portal.md` の「参加の条件(G-02・G-02-R1)」)
- 問題: メールのリンクと通常のパスワードのログインはトークン上区別できない(どちらも `password`)。Google のセッションでパスワードを設定して入り直すと、旧方式の「30分以内の password = メールの受信の証明」を満たし、招待の承諾から注文の閲覧まで進めた。
- 修正: 参加(招待の承諾)は、サーバーが発行して招待されたメールへ送る確認コードの入力だけで受け付ける。ログイン方法・`email_verified`・UID・メールの一致は証明として扱わない(旧 `mailboxProven`・`emailLinkRequired` を削除)。
  - コード: 8桁、ソルト付きハッシュで保存・定時間で照合。UID・メール・招待の世代に結び付け、10分・1回・誤り5回まで。送り直しは1分あけて5回まで。承諾と同じトランザクションで消費。
  - 招待の一覧は会社名を返さない(会社名は確認コードのメールに書く)。辞退はコードなしで可。
  - 送信は注文メールと同じ設定(Resend)に従う。`dealerPortalApi` が送信用のシークレットを参照するようになった。エミュレータのテストだけ、`demo-` のプロジェクトでコードをテスト用の文書に書く(本番の環境ファイルは変更なし)。
  - 画面: 「確認コードを送る」→ 8桁の入力 →「参加する」。
- G-01・G-03・G-04 の対応と、注文情報の分離(自社宛ての明細だけ)は維持。ログイン方法を変えて別の UID になった場合、所属は移らず、旧 UID の無効化・再招待・確認コードで承諾する(旧 UID は再招待を先取りできない)。
