## 変更内容(詳細は `docs/dealer-portal.md` の「確認済みの端末」)
- 問題: 未登録の Microsoft が既存の UID に入ったセッションから、パスワードを設定して Microsoft の連携を外し入り直すと、トークンが本人と同じ形になり、会社・一覧・詳細を取得できた。
- 対策: 担当者の閲覧(context・companies・list・get・setAssignments)を、メールの確認コードで確認した端末からだけ受け付ける。ログイン方法・連携の状態・email_verified では判断しない。
  - 参加の承諾・Microsoft の登録・端末の確認(新しい操作 sendDeviceCode / verifyDevice)でコードを確かめたとき、サーバーが端末の値を1回だけ返し、画面が端末に保存する。サーバーはハッシュだけを UID に結び付けて保存(Rules でクライアントの読み書きを拒否)。期限180日・1人10台。
  - 連携の解除・ログイン方法の変更ではサーバーの記録は消えない(最初の API の前に解除しても同じ)。担当者の無効化で端末を消す。
  - 復旧: 新しい端末・保存を消した端末は、承認済みのメールの確認コードでいつでも確認できる。心当たりのない Microsoft は登録せずに解除できる(画面に「連携を解除する」)。
- G-02・MS-02・MS-03 の対応は維持(参加・Microsoft の登録は従来どおり確認コード。登録でも端末を確認済みにするので、コードは1回で済む)。
- Low(発注先の一括保存と Rules の参照回数): コードは変更せず、影響と対応案を資料に記録(本番運用中の施設設定の保存処理に及ぶため、採否の判断を待つ)。
