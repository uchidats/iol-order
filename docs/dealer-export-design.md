# ディーラー受注一覧の印刷・PDF・Excel出力(R07)設計案

状態: **設計済み・実装待ち**(2026-11-03、Claude Code が起案、同日ユーザーが基本方針を採用し下記を決定)。コードの実装・Functions の変更・デプロイは未着手。
前提: ディーラー専用画面の第1段階(`docs/dealer-portal.md`)。注文の受付・検索・権限管理は変更しない。

## 0. 決定事項(2026-11-03、ユーザー)

1. 印刷と PDF は共通の A4 帳票。PDF はブラウザの「PDF に保存」を使う(独自の PDF 生成は持たない)。
2. Excel は**最初から `.xlsx`** で実装する。CSV は当面不要。
3. Excel の「曜日」列は採用。「区分」列は意味を明確にしたうえで採用する → 本書では **「レンズ区分」**(単焦点 / 多焦点 / トーリック / 多焦点トーリック)と定義する(§4)。取消済み・テスト注文はディーラーの一覧に元々含まれない(サーバーが返さない)ため、注文の状態(通常・取消済み・テスト)の列は設けない。将来、状態を出す必要が出たら別の列「状態」として改めて決める。
4. 出力の上限は **注文 1,000 件 または 明細 3,000 行**。
5. 出力の範囲は、注文日順 = 検索条件に一致する全件、手術日順 = 画面に読み込まれている週の範囲。
6. ファイル名は **`受注一覧_YYYYMMDD-HHMM`** を基本とし、日時は日本時間、拡張子は形式に応じて付ける(`.xlsx`。PDF はブラウザが付ける)。

追加の注意(同日):
- 手術日順で1週の取得上限(100件)に達して結果が一部のみのときは、**出力の前に警告**し、**帳票・Excel にも不完全であることを明示**する(§5)。
- Excel は1レンズ1行・セル結合なし。
- `.xlsx` の生成方法は、軽量ライブラリと自前 writer の保守性・安全性を比較してから決める(§6-4。実装の着手時に確定)。
- 既存の閲覧権限を維持し、他社宛ての明細・備考などは出力しない。
- スマホ・PC の両方に対応する。

## 1. 目的と方針(依頼の整理)

- ディーラーが受注情報を印刷・保存・社内管理できるようにする。
- 画面のシンプルな見た目を保つ。ボタンは「出力」1つにまとめ、押すと「印刷・PDF」「Excel」を選ぶ。
- 出力の範囲は、いま画面で選んでいる条件(並び順・医療機関・注文日の期間・手術日の週)と一致させる。表示中の20件だけでなく、条件に該当する受注全体を出す。
- 自社宛ての明細だけを出力する。元の注文の備考・入力者・他社の明細は、いまの API が返さないので、出力にも含まれない(新しい開示はしない)。
- スマホ・PC のどちらでも使える。

## 2. 画面配置

「出力」は並び順の切り替えの行の右端に置く(注文日順・手術日順の両方で同じ場所。補助ボタンの大きさ 36px・グレー)。

```
PC / スマホ共通(受注一覧の上部)
┌──────────────────────────────────────────────┐
│ 医療機関  ☑テスト眼科 ☑○○クリニック  [全て][担当施設]     │
│ [注文日順][手術日順]                         [出力 ▾] │
│ 注文日 ⓘ  [10/1 ×] 〜 [12/31 ×] [検索]      (注文日順のみ) │
│ 12件                                                     │
│ ┌ 注文カード … ┐                                        │
└──────────────────────────────────────────────┘

「出力」を押したとき(ボタンの下に小さな選択肢。スマホも同じ)
┌───────────────────────────────┐
│ 出力する範囲                              │
│  手術日順 / 医療機関 2施設 /               │
│  11月2日の週〜11月16日の週(表示中の週)       │
│ ──────────────────────────── │
│  🖨 印刷・PDF                              │
│  ▤ Excel(.xlsx)で保存                       │
│ ──────────────────────────── │
│  自社宛ての明細のみ。備考・他社の明細は含みません │
└───────────────────────────────┘
```

- 「印刷・PDF」は同じ帳票。ブラウザの印刷ダイアログで「PDF に保存」を選ぶと PDF になる(別の PDF 生成は持たない。§6-3)。
- 手術日順で一部のみの週(`truncated`)が範囲に含まれるときは、この選択肢の中に「11月16日の週は件数が多く一部のみです。出力も一部になります」と**出力の前に警告**を出す(§5)。
- 「出力する範囲」は、いま画面で選んでいる条件をそのまま文字で示す。出力の前に条件を変える UI は置かない(条件は一覧側で変える)。
- 320px でも「[注文日順][手術日順] … [出力]」は1行に収まる(切り替え2つ ≈ 180px + 出力 ≈ 60px)。

### 印刷プレビュー(帳票の表示)

「印刷・PDF」を選ぶと、一覧の代わりに帳票を画面に表示する(詳細画面と同じく、戻ると読み込んだ一覧と位置は保つ)。

```
┌──────────────────────────────────────────────┐
│ [← 一覧へ戻る]                       [印刷する]  │
│                                                  │
│  受注一覧(手術日順)              ○○メディカル株式会社 │
│  医療機関: テスト眼科、○○クリニック                 │
│  手術日: 2026/11/2 の週 〜 2026/11/16 の週            │
│  検索時点: 2026/11/03 15:30   出力: 2026/11/03 15:32 │
│  注文 12件 / 明細 18行 / 合計 21枚                   │
│  (帳票本体 §3)                                     │
└──────────────────────────────────────────────┘
```

- 印刷時(`@media print`)はヘッダー・メニュー・ボタンを隠し、帳票だけを出す。
- 別タブ(`window.open`)にしないのは、ポップアップの抑止・ログイン状態の引き継ぎ・スマホでの戻り方を考えてのこと。同じ画面の中の「帳票表示」なら、スマホでも帳票をそのまま読め、共有メニューから印刷・PDF にできる。

## 3. 帳票のサンプル(A4 縦・印刷)

共通のヘッダー(毎ページ): 帳票名(並び順)・会社名 / 条件(医療機関・期間)・検索時点・出力日時・出力者(担当者名)・件数。
共通のフッター: 「自社宛ての明細のみを記載。備考・他社の明細は含みません。」ページ番号はブラウザの既定のヘッダー/フッターに任せる(第1段階。§6-3)。

### 3-1. 注文日順(1注文ごとにまとまり。新しい順)

```
受注一覧(注文日順)                       ○○メディカル株式会社
医療機関: 全施設(3)   注文日: 2026/10/1 〜 2026/12/31
検索時点 2026/11/03 15:30  出力 2026/11/03 15:32  注文12件 / 明細18行 / 21枚
──────────────────────────────────────────────────────────
注文番号      医療機関       注文日時          手術日   モデル        度数    枚数  担当医
──────────────────────────────────────────────────────────
20261103-004  テスト眼科     2026/11/03 09:12  11/10(火) DIB00V       +21.0D   1   内田
                                                11/10(火) DIB00V       +20.5D   1   内田
                                                11/17(火) ZCT225      +19.0D   2   内田
20261102-011  ○○クリニック  2026/11/02 17:40  11/12(木) SN60WF      +22.0D   1   佐藤
──────────────────────────────────────────────────────────
```

- 注文番号・医療機関・注文日時は、その注文の1行目だけに書く(画面のカードと同じ読み方)。注文のまとまりは途中で改ページしない(`break-inside: avoid`)。
- モデルはトーリックなら型番(画面と同じ `toricModel || model`)。メーカー名は第1段階では出さない(§6-2)。

### 3-2. 手術日順(手術日 → 医療機関 → 明細。納品・準備の確認用)

```
受注一覧(手術日順)                       ○○メディカル株式会社
医療機関: テスト眼科、○○クリニック   手術日: 11/2 の週 〜 11/16 の週
──────────────────────────────────────────────────────────
手術日        医療機関       注文番号      モデル        度数    枚数  担当医
──────────────────────────────────────────────────────────
11/10(火)
              テスト眼科     20261103-004  DIB00V       +21.0D   1   内田
              テスト眼科     20261103-004  DIB00V       +20.5D   1   内田
              ○○クリニック  20261030-002  SN60WF      +22.0D   1   佐藤
                                                  11/10(火) 小計      3枚
11/12(木)
              ○○クリニック  20261102-011  SN60WF      +22.0D   1   佐藤
                                                  11/12(木) 小計      1枚
11月9日の週: 受注はありません   (予定のない週・日は画面と同じ扱いで1行)
──────────────────────────────────────────────────────────
```

- 手術日ごとの小計(枚数)は第2段階で足す(第1段階は行だけ)。
- 1週に 100 件を超える週(`truncated`)は、ヘッダーに「※ 11月16日の週は一部のみ(件数が多いため)」と赤字ではなく太字で明記し、該当の週の見出しにも「(一部のみ)」を付ける。黙って欠けさせない。Excel は「出力条件」シートに同じ注記を書き、「明細」シートの先頭行にも注記を1行入れる。

### 3-3. 印刷の指定(案)

- `@page { size: A4; margin: 12mm }`。文字 10.5pt、罫線は薄いグレー、色は使わない(モノクロ印刷前提。テーマカラーも使わない)。
- 見出し行は毎ページ繰り返す(`thead { display: table-header-group }`)。明細行は途中で切らない。
- 医療機関名・担当医名は列の中で折り返す(切らない)。長い場合は列幅を自動調整せず、折り返しで対応する。

## 4. Excel 出力(1レンズ1行)

1行目を見出しにした平らな表(セル結合なし)。フィルタ・並べ替え・ピボットで使えることを優先する。

| 列 | 内容 | 例 | 備考 |
| --- | --- | --- | --- |
| A 注文番号 | | 20261103-004 | 文字列 |
| B 医療機関 | | テスト眼科 | |
| C 注文日 | 日本時間 | 2026/11/03 | 日付セル |
| D 注文時刻 | 日本時間 | 09:12 | |
| E 手術日 | | 2026/11/10 | 日付セル |
| F 曜日 | | 火 | 並べ替えの補助 |
| G 明細No | 自社分だけで 1 から | 1 | 数値 |
| H メーカー | 第2段階 | Johnson & Johnson | §6-2。第1段階は列を設けない |
| I モデル | | DIB00V | 非トーリックのモデル名 |
| J トーリック型番 | トーリックのみ | ZCT225 | 空欄 = 非トーリック |
| K 度数 | | +21.0D | 文字列のまま(「+」「D」を保つ) |
| L 枚数 | | 1 | 数値 |
| M 担当医 | | 内田 | 記録がなければ空欄 |
| N レンズ区分 | 単焦点 / 多焦点 / トーリック / 多焦点トーリック | トーリック | 明細の `isMultifocal`・`isToric` から。注文の状態(取消済み・テスト)ではない(§0-3) |

- 1シート目「明細」。2シート目「出力条件」(会社名・医療機関・期間・並び順・検索時点・出力日時・出力者・件数・「自社宛ての明細のみ」の注記)。注文ごとの集計シートは第3段階で検討。
- 出さないもの: メール送信の状態(社内向けの画面情報)、備考、入力者、他社の明細、注文全体の件数・枚数(他社分が推測できるため。いまも API が返さない)。
- ファイル名: `受注一覧_20261103-1532.xlsx`(出力日時。日本時間、`YYYYMMDD-HHMM`)。条件はファイル名に入れず「出力条件」シートに書く。
- 形式: 最初から `.xlsx`(§0-2、§6-4)。CSV は作らない。
- 安全: 医療機関名・担当医名・モデル名は人が入力した値だが、xlsx では**文字列セル**(数式セルにしない)として書くため、先頭が `=` `+` `-` `@` でも数式として解釈されない。生成時に数式セルを一切作らないことをテストで確かめる。

## 5. 出力範囲とデータの取得(既存 API のまま)

| 並び順 | 出力の範囲 | 取得の方法 |
| --- | --- | --- |
| 注文日順 | **いまの検索条件に該当する全件**(医療機関・注文日の期間。表示中の20件に限らない) | 既存の `list` を、画面と同じ条件で `nextCursor` がなくなるまで続けて呼ぶ(1回 100 件まで `pageMax`)。カーソルは検索時点(`asOf`)で固定されるので、途中で新しい注文が反映されても同じ時点の内容で揃う |
| 手術日順 | **画面に読み込んでいる週の範囲**(例: 11/2 の週〜11/16 の週。「もっと見る」で広げた分を含む) | 既存の `week` を、範囲の各週について呼ぶ(表示済みの週はその結果を使い、未読の週は読む)。`truncated` の週があれば**出力の前に警告**し、帳票・Excel に「一部のみ」と明記(§2・§3-2) |

- 手術日順の「条件に該当する全体」は将来の週まで際限がないため、「表示中の週の範囲」を出力の範囲とする(範囲を広げたいときは先に「もっと見る」で週を増やす。帳票とメニューに範囲を明示する)。
- 上限: 1回の出力で **注文 1,000 件 または 明細 3,000 行**(目安。1,000 件 ≈ `list` 10 回)。超えたら「期間を分けて出力してください」と知らせ、途中までを出さない。
- 進捗: 取得中は「取得中… 240件」と出し、「中止」を置く。取得の途中で `restart`(読み終えた範囲に新しい索引が反映)が返ったら、出力を中止して「検索をやり直してから出力してください」と知らせる。
- 取得した内容は出力のためだけに使い、画面の一覧(20件ずつの表示・カーソル)には影響させない(一覧の状態・スクロール位置は保つ)。
- 1行ごとの権限の確認(会社・担当者・許可・施設)は既存の `list`/`week` の中で毎回行われるので、出力のために権限の処理を増やさない。

## 6. 技術的な検討事項

### 6-1. 既存の API だけで足りるか
- 足りる(第1段階)。`list` は注文番号・医療機関・注文日時・明細(手術日・モデル・トーリック型番・度数・枚数・担当医)を返し、`week` は加えてメーカー名を返す。
- サーバーを変えずに済む半面、**出力の記録(監査ログ)が残らない**・**上限がクライアント任せ**になる。社内管理の観点で「誰がいつ何件出力したか」を残したければ、第3段階でサーバーに `export` 操作を足す(§7)。

### 6-2. メーカー名
- 注文日順の `list` は一覧用にメーカー名を省いている(画面の都合。`listLinesOf`)。`week`・`detail` は返しているので、開示の範囲としては既に自社に見えている情報。
- 第2段階で `listLinesOf` に `manufacturer` を足す(Functions の1行。配備が要る)。第1段階の Excel はメーカー列なし(モデル名で判別できる)。

### 6-3. 印刷・PDF
- PDF は**ブラウザの印刷ダイアログの「PDF に保存」**で作る。PC(Chrome/Edge/Safari/Firefox)と Android Chrome は標準で選べる。
- iPhone/iPad の Safari は、印刷プレビューをピンチで開いて共有 → 「"ファイル"に保存」という手順になり、分かりにくい。マニュアルに手順を書く。スマホで PDF をよく使うなら、第3段階でサーバー側の PDF 生成(Functions で HTML → PDF。ライブラリとメモリが要る)を検討する。
- ページ番号・総ページ数を帳票の中に入れるには `@page` の余白ボックスが要るが、対応がブラウザで揃っていない。第1段階はブラウザの既定のヘッダー/フッター(日付・URL・ページ)に任せる。
- Firefox/Safari で `thead` の繰り返し・`break-inside` の効き方に差があるため、3ブラウザで印刷の見た目を確認する(Playwright の `emulateMedia({ media: "print" })` で構造と非表示を検証。実際の改ページは手動で確認)。

### 6-4. Excel(.xlsx)の作り方(実装の着手時に、比較のうえ確定する)
前提: 本リポジトリは外部スクリプトを実行時に読み込まない(CDN なし。OCR の Tesseract も停止中)。使うなら**ファイルをリポジトリに同梱**し、`stamp-assets` の対象にする。必要な機能は「文字列・数値・日付のセル、列幅、1行目の固定、オートフィルタ、2シート」だけ。

| 観点 | 軽量ライブラリを同梱(例: `write-excel-file`〔MIT〕、SheetJS Community〔Apache-2.0、npm の 0.18.x〕) | 自前 writer(無圧縮 ZIP + XML、依存なし) |
| --- | --- | --- |
| 実装の手間 | 小さい(呼ぶだけ) | 150〜200 行程度。CRC32・ZIP のヘッダー/中央ディレクトリ・`[Content_Types].xml`・`workbook.xml`・`sheet*.xml`・`styles.xml`(日付の表示形式1つ) |
| 配信サイズ | 数十〜数百 KB(SheetJS は 400KB 前後、`write-excel-file` は圧縮用の `fflate` を含め 100KB 前後。いずれも目安。同梱前に実測) | 数 KB |
| 保守 | 更新の追従・脆弱性の確認が要る。SheetJS は npm 版の更新が止まり、新しい版は独自配布(同梱の方針と相性が悪い) | 外部の更新なし。仕様(OOXML の最小構成)は安定しており、必要な機能が増えなければ変更は少ない |
| 安全性 | 第三者コードをディーラー画面で実行する。ライセンス表記・版の固定・改ざん防止(同梱ファイルのハッシュ)が要る | 第三者コードなし。書くのは自分たちの XML だけで、入力はすべてエスケープして文字列セルに入れる |
| 機能の余地 | 書式・結合・数式・画像まで一通り | 必要分だけ。凝った書式(条件付き書式など)が要るなら作り足す |
| 検証 | ライブラリ自体は検証済み。生成物を Excel・Numbers・LibreOffice で開いて確認 | node:test で生成物を解凍(無圧縮なのでオフセットで取り出せる)して XML を検証し、Excel・Numbers・LibreOffice で開けることを手動で確認 |

- 起案時の見立て: 必要な機能が少なく、第三者コードを持ち込まない方針と合うため**自前 writer が有力**。ただし決定は実装の着手時に、候補ライブラリの実測サイズ・ライセンス・最終更新日を確認したうえで行う(§0 追加の注意)。
- どちらでも共通: 数式セルを作らない。日付は日付セル(`yyyy/m/d`)、度数は文字列、枚数・明細Noは数値。

### 6-5. スマホでの保存
- `Blob` + `<a download>` で保存。iOS Safari は「ファイル」に保存またはダウンロードフォルダに入る。日本語のファイル名は問題ない。
- 保存後に「保存しました。ファイルアプリで開けます」と短く出す(スマホは保存先が分かりにくい)。

### 6-6. 日付・時刻・文字
- 日本時間で統一(画面と同じ `jstDate`/`formatJstDateTime`)。手術日は `YYYY-MM-DD` の文字列を日付セル(`yyyy/m/d`)にする。
- 度数は文字列のまま(`+21.0D`)。数値にすると「+」「D」が落ち、トーリックの円柱度数の表記にも対応しにくい。
- XML のエスケープ。数式セルを作らない(§4)。

### 6-7. 実装の置き場所(案)
- `src/domain/dealer-report.js`(純粋関数): 取得した注文 → 帳票の行(注文日順・手術日順)・Excel の行・出力条件の文字。node:test で検証。
- `src/domain/xlsx-writer.js`(純粋関数。§6-4 でライブラリを選んだ場合は、その呼び出しをここに閉じ込める)。
- `src/dealer/dealer-export.js`: 「出力」ボタン・メニュー・取得ループ・進捗・保存。`dealer-app.js` から一覧の状態(条件・読み込み済みの週・`asOf`)を受け取る。
- `styles.css`: `.dealer-report`(画面表示)と `@media print`(ディーラー画面に限定。医療機関側の画面の印刷には影響させない)。
- `dealer.html`・import map は `node scripts/stamp-assets.mjs` の対象。
- マニュアル `docs/dealer-manual/02-orders.md` に「出力」の節(範囲・上限・iPhone での PDF の手順)。

### 6-8. 権限・設定
- 出力できる人: 閲覧できる人全員(閲覧者を含む)。出力は閲覧と同じ情報なので、新しい権限は作らない。会社管理者が「閲覧者には出力させない」設定を望む場合は第3段階(会社文書の設定 + サーバー側の `export` で判定)。
- 医療機関側に「印刷・Excel 出力を許可する」設定を置くかは、開示方針の話(`dealerPortalGrants` の `disclosure`)。いまの許可は「閲覧」を許可しているので、第1段階では新しい設定を作らない。医療機関から要望があれば、許可の画面の説明文に「印刷・保存を含む」と明記する対応から始める。

### 6-9. テスト
- unit: 帳票の行・Excel の行・xlsx の生成(エスケープ・日付・数式セルがないこと・上限・一部のみの注記)。
- ブラウザ(ディーラーの偽 API): 「出力」の位置と大きさ(320/390/1100px)、メニューの範囲表示が条件と一致、取得ループ(複数ページ・`restart`・上限超え・中止)、帳票表示の構成と `@media print` での非表示、ダウンロード(`page.waitForEvent("download")` でファイル名と中身)。
- Functions: 第1段階は変更なし。第2段階(メーカー列)は `listLinesOf` のテストに1項目追加。
