# 施設別関連リンク（R18）

承認済み計画に基づく実装。標準5リンクは src/domain/related-links.js の固定ID・名称・URL・順序を参照する。未設定の標準リンクは表示する。標準リンクの施設文書に保存するのは enabled、updatedBy、updatedAt のみで、文書の削除は許可しない。

施設独自のリンクは facilities/{facilityId}/relatedLinks/{linkId} に1リンク1文書で保存する。IDは custom-UUID で生成し、名前やURLを変更しても維持する。フィールドは name（空白のみ不可・100文字以内）、url（HTTPS・2048文字以内・認証情報/制御文字/バックスラッシュ不可）、enabled（bool）、sortOrder（非負の整数）、updatedBy（本人UID）、updatedAt（serverTimestamp）。有効な施設所属者だけが閲覧でき、管理者・副管理者だけが変更できる。運営者でも未所属ならこのコレクションにはアクセスできない。

Repositoryの listRelatedLinks と設定APIの saveRelatedLinks(facilityId, {upserts, deletes}) を利用する。変更文書だけをバッチで保存する。標準のチェックを未設定のONから変えていなければ文書は作らない。施設への一括登録・データ移行は不要。Functionsは追加・変更しない。

施設設定では「注文メール」の次に表示する。標準は読み取り専用の名称・URLと表示チェック。独自リンクは追加・鉛筆で編集・ゴミ箱で削除・↑、500msの入力停止後に有効な行だけ保存する。不正な行の草稿は他の有効な行を妨げない。保存中の編集は後続で直列に保存し、入力欄は再描画しない。削除も同じ保存列で処理し、成功後に行を除く。失敗は入力と削除待ちを保持し、再試行を表示する。

離脱時は入力タイマーと保存中処理を待つ。未保存の草稿・失敗が残れば「この画面を離れると、未保存の入力や保存に失敗した変更が破棄されます」と明示して確認する。戻るボタン・ヘッダーメニュー・ヘルプ/紹介へのハッシュ移動を対象とする。再読み込み/タブを閉じるときはブラウザ標準の確認に従う。

注文画面では「関連リンク」を初期閉状態で表示し、標準→独自の順に並べる。表示0件なら欄を隠す。取得失敗は未設定として扱わず、案内を表示して注文入力は継続する。外部リンクは文字として描画し、別タブ・noopener noreferrerを指定する。

保存成功時は同じ端末のリンク部分だけを更新する。他端末は再読み込み・施設を開き直した際に反映する。施設IDと読込世代を確認し、旧施設や保存前の遅延した結果は適用しない。Webを反映する際にはFirestore Rulesも必要。公開時はユーザーの明示指示に従い、Rules→main/Webの順で反映する。本番データの一括移行・変更は不要。
